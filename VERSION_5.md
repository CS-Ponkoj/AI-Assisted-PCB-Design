# Version 5: PCB Review Copilot

## Summary

Version 5 adds a Gemini-first PCB Review Copilot on top of the existing generated handoff workflow. The current Base, Ollama LLM, and Gemini API requirement extraction modes remain unchanged. The design package, readiness review, PCB visual, detailed tables, and exports are still generated by the existing pipeline.

The copilot only appears after a handoff exists. It reviews the generated package and answers questions using the package data as its source of truth.

## What Changed

### PCB Review Copilot

The Streamlit app now includes a review panel after the PCB layout visual. Users can ask questions such as:

- What are the design risks?
- Explain the power budget.
- What should I check before fabrication?
- Create a bring-up plan.
- Why was this sensor selected?
- What happens if I remove a sensor?

The copilot is intentionally scoped to review, explanation, and risk highlighting. It does not silently change the generated design.

### Gemini-First Copilot Mode

The user-facing copilot uses Gemini by default and answers from a compact review context built from:

- parsed requirement
- selected components
- unsupported requirements
- BOM
- pin map
- netlist
- power budget
- readiness review
- layout guidance
- fabrication checklist
- bring-up checklist

If Gemini is missing, busy, unavailable, or returns invalid JSON, the UI switches to Local Review Mode. Local Review Mode shows source-grounded questions and answers deterministically from the generated handoff. It does not use Ollama.

### Compact Suggested Questions

Suggested questions are displayed in a compact scrollable box beside the chat transcript so the copilot panel does not push the rest of the handoff down the page.

Optional environment variables:

```text
REVIEW_COPILOT_MODEL=gemini-2.5-flash-lite
REVIEW_COPILOT_MAX_CONTEXT_CHARS=9000
REVIEW_COPILOT_MAX_OUTPUT_TOKENS=550
```

### Source-Grounded Answers

Each answer includes source labels such as:

- BOM
- Netlist
- Power Budget
- Readiness Review
- Fabrication Checklist
- Bring-Up Checklist

This makes the copilot useful as a review companion instead of a general-purpose chatbot.

## Failure Isolation

Version 5 is an addition, not a replacement. If the copilot fails:

- requirement parsing still works
- Base, Ollama, and Gemini extraction still work
- design package generation still works
- readiness review still works
- PCB visual still works
- exports still work

The UI catches copilot errors and keeps the generated handoff available.

## Validation

The upgrade should be checked with:

```bash
python -m py_compile app.py src\base_assistant.py src\data_loader.py src\design_generator.py src\exports.py src\gemini_assistant.py src\ollama_assistant.py src\parser.py src\readiness.py src\review_copilot.py src\validation.py src\visuals.py
python -m unittest
```

## Scope

The copilot is a review assistant for the generated prototype handoff. It does not add real PCB autorouting, KiCad generation, Gerber generation, electrical simulation, or manufacturing signoff.
